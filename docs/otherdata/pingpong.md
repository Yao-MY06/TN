# 基于机器视觉的低成本乒乓球智能裁判方案

面向市场设计成“独立裁判终端”：摄像头、边缘计算板、麦克风、扬声器、显示屏和电源集成在一个盒子里。单摄像头可以覆盖普通业余比赛的基本计分，但擦边、被人体遮挡、强拖影等情况，由语音或按钮修正。

## 1. 实施顺序

1. 先在电脑上用公开数据实现发球/回合/二跳/出界状态机对应算法和比分 UI（自采帧微调 YOLOv8n/YOLO11n  加入轨迹平滑和落台候选检测+ TTnet 或者自编算法），实现完再考虑部署到硬件平台上做测试及修改。
2. 固定摄像头，完成四点标定、球台 ROI。
3. 将算法部署到硬件平台上进行测试。
4. 接入语音离线唤醒和固定口令，加入撤销、修改、日志。
5. 实现第一版的较高成本样机后，再考虑如何降低成本（降低分辨率帧率，改良算法后减少对应的计算难度，从而可以选取更低成本的开发板；显示屏改用LED记分牌）。

## 2. 实体方案

### 2.1 摄像头和安装

- 采用横向 16:9 画面，建议 1920×1080、60 fps，预算够的话买120 fps 能更贴合TTNet 模型。（后面再尝试换更低分辨率帧率的摄像头降低成本）
- 摄像头固定在球台一侧后方的高位支架，画面同时包含整张球台、球网和两侧落地区域。
- 镜头视野略大于球台，手动对焦、曝光和白平衡固定；球台四角贴高对比度小标记，便于自动或半自动标定。
- 球台区域用四点透视变换映射到标准平面坐标。ITTF 标准球台为 2.74 m × 1.525 m，高 0.76 m。

### 2.3 独立终端的软件和交互

1. **标定**：首次运行手动点选球台四角和球网线，保存透视矩阵。
2. **球检测/追踪**：摄像头帧先裁剪球台 ROI；用轻量 YOLO 检出候选球，再用 Kalman/ByteTrack 平滑。球很小、模糊时，用连续三帧热图网络 TrackNet/TTNet 补充。
3. **落台与出界判断**：把球中心映射到球台平面，寻找“向下接近桌面后向上”的轨迹转折；根据球网线把球台分成左右两半。
4. **计分状态机**：记录发球方、最近一次合法落台侧、二跳、擦网、出界等事件。普通规则下，一方未能让球在对方半台合法落台，则另一方得分。11 分制、领先 2 分、每 2 分换发球，10:10 后每分换发球，均做成可配置项。
5. **语音纠错**：离线唤醒词可设为“小裁判”；唤醒后识别“左方加一分、右方加一分、撤销上一分、重置比分、确认这一分”等固定短语，采用关键词/正则解析，避免开放式语音理解带来的误操作。识别不到时保留实体按键作为后备。
6. **开机恢复**：插电自动启动，断电自动恢复最近比分。

### 2.4 判分策略

“检测器 + 几何 + 状态机”：

```text
视频帧 -> 球位置序列 -> 球台/球网坐标 -> 落台、擦网、出界事件 -> 乒乓球规则状态机 -> 得分 -> 画面/语音/日志  
```

状态机设置以下保护：

- 连续若干帧没有可靠球位置时暂停自动计分，不把一次漏检直接当成失分。
- 自动加分后保留“撤销”和“左/右加一分”命令，语音纠错只修改比分状态，不改动原始视频和事件日志。
- 用实拍球局做验收，按普通落台、出界、擦网、擦边、遮挡、光照变化分别统计；目标是普通球路的得分结果达到约 95% 以上，困难球路允许人工确认。

## 3. 算法选择

YOLO 可以作为第一版球检测器，但单独使用 YOLO 往往会漏掉小球、运动模糊和遮挡。建议按以下优先级实施：

### 3.1 低成本 MVP

- 用 500–2,000 张从本机摄像头截取的球台帧，标一个类别 `pingpong_ball`，训练 YOLOv8n/YOLO11n；训练时加入模糊、缩放、亮度和遮挡增强。
- 推理时只在球台 ROI 内运行，必要时将 ROI 放大或切成 2–4 个小块；检测结果交给 Kalman/ByteTrack 做时间连续性。
- 用 OpenCV 的透视变换、轨迹拟合和状态机做落台判定。这一版通常比直接训练“得分分类器”更易解释和调试。

### 3.2 球很小或拖影明显时

- TrackNet/TrackNetV2 类网络输入连续多帧，输出球中心热图；它原本面向网球/羽毛球，但方法可迁移到乒乓球。
- TTNet 是更完整的乒乓球方案，包含全局/局部球检测、落台和擦网事件检测、人体/球台/记分牌语义分割。它原始实现较重，直接塞进低端边缘板卡会增加工程量。

### 3.3 可直接参考的实现

- [TTNet PyTorch（TinDang97）](https://github.com/TinDang97/TTNet-Realtime-for-Table-Tennis-Pytorch)：包含球检测、事件检测和语义分割模块。
- [TTNet PyTorch（maudzung）](https://github.com/maudzung/TTNet-Real-time-Analysis-System-for-Table-Tennis-Pytorch)：另一份可读性较好的复现。
- [TrackNet 非官方 PyTorch 实现](https://github.com/yastrebksv/TrackNet)：连续帧热图追踪思路，适合改成乒乓球版本。
- [table-tennis-detection](https://github.com/lukianchenko/table-tennis-detection)：YOLO/轨迹检测类工程参考。
- [table-tennis-ball-detection](https://github.com/Rahimdzx/table-tennis-ball-detection)：包含乒乓球轨迹和比赛事件分析的工程示例。

## 4. 数据集、论文和影像来源

### 4.1 最值得优先使用：OpenTTGames

[OSAI OpenTTGames Dataset](https://lab.osai.ai/)

- 5 个训练视频（每个约 10–25 分钟）和 7 个测试短视频；全高清、120 fps、工业相机拍摄。
- 4,271 个人工标注事件，包含 `bounce`（落台）、`net hit`（擦网）和空事件。
- 提供球在帧中的 `(x,y)` 坐标、人体/球台/记分牌分割掩码和事件帧号；标注是“事件中心”的，事件前 4 帧、事件后 12 帧有更密集的球和掩码信息。
- 训练视频单个文件可达数 GB，但标注压缩包只有 MB 级；做实验时先下载测试视频和标注。
- 许可为 CC BY-NC-SA 4.0，商业产品或对外分发前必须再次核对许可条件。
- 对本项目最有用的是落台、擦网、球坐标和球台分割；它不是完整的“谁得分”标签，因此仍需自己编写规则状态机。

### 4.2 乒乓球动作/视频数据

- [TTStroke-21 / MediaEval Sport Task](https://multimediaeval.github.io/editions/2022/tasks/sportsvideo/)：21 类乒乓球击球动作，适合击球/动作识别和研究，不是直接的得分数据集；部分原始视频按挑战赛规则提供，下载前查看访问条件。
- [TTNet 论文（CVPR Workshops 2020）](https://openaccess.thecvf.com/content_CVPRW_2020/html/w53/Voeikov_TTNet_Real-Time_Temporal_and_Spatial_Video_Analysis_of_Table_Tennis_CVPRW_2020_paper.html)：OpenTTGames 的配套论文，解释球检测、事件 spotting 和分割任务。
- [OpenTTGames 标注与视频下载页](https://lab.osai.ai/)：包含每个视频、标注 zip 和许可证的直接链接。

### 4.3 图片/目标检测数据

- [Actual Table Tennis Dataset（Roboflow，1050 张）](https://universe.roboflow.com/tennisdataset/actual-table-tennis-dataset/dataset/1)：球的目标检测图片和多种导出格式，适合预训练/验证；使用前核对 Roboflow 页面上的具体许可证。
- [Ping-pong ball detection（Roboflow，194 张）](https://universe.roboflow.com/dogs-classifier/ping-pong-ball-detection-sszkb/dataset/1)：规模较小，可用于快速跑通 YOLO 标注格式和推理流程；不能代替本机视角数据。
- [Table Tennis Ball Position Detection Dataset（Kaggle）](https://www.kaggle.com/datasets/ketzoomer/table-tennis-ball-position-detection-dataset)：提供比赛视频中的球位置数据，适合做位置回归/检测实验；下载通常需要 Kaggle 账号，使用前核对数据许可。

### 4.4 轨迹和三维数据（辅助用途）

- [Table Tennis Ball Trajectories with Spin（Edmond，DOI 10.17617/3.BIVUVL）](https://edmond.mpg.de/dataset.xhtml?persistentId=doi:10.17617/3.BIVUVL)：主要是带旋转参数的球轨迹数值数据，不是用于训练像素级检测器；可用于轨迹预测、物理仿真和异常样本构造。
- [TT3D: Table Tennis 3D Reconstruction](https://cogsys-tuebingen.github.io/tt3d/)：面向单目视频三维重建的研究数据，适合后续做 3D 落点和速度分析，第一版计分可以暂不使用。

### 4.5 自采数据

公开数据集的相机高度、球台颜色、球员位置和光照与实际安装通常不同。建议自己录制 2–4 小时：正常对拉、发球、擦网、出界、擦边、球被人体遮挡、不同颜色球台和夜间灯光。抽帧后只标 `ball`、球台四角/球网线和事件类型，先做 1,000 张高质量样本，再按误判集中场景增量标注。
